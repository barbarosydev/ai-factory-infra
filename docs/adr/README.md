# Architecture decision records

These records explain why the repo is built the way it is. Each one describes the current state and the reasons, so a new reader or agent can tell a deliberate choice from an accident. Versions and measured values are not repeated here: versions live in the code, measurements in [architecture.md](../architecture.md), procedures in the [runbook](../runbook.md).

Each record has the same sections: Status, Date, Context, Decision (reasons included), and Consequences (with Known limitations where there are any). A record stays within about one screen. When a decision changes, the record is edited or replaced and the index below is updated.
